# WVP-Pro 编程规范

本文档基于当前代码库的实际风格整理，原则是：**新代码必须遵守，存量代码逐步靠拢**。文中会明确标注现有例外，避免把历史问题当成标准。

适用范围：后端 `src/main/java/com/genersoft/iot/vmp/`，前端 `web/`，数据库脚本 `数据库/`。

## 一、总体原则

- Controller 只做参数校验、调用 Service、组织响应；业务逻辑、SQL、Redis 操作下沉到 Service/DAO。
- 修改 bug 时优先重构出可复用方法，避免叠加 `if` 分支和重复清理逻辑。
- 不整文件格式化、不无关重排；只改必要行，降低 review 成本。
- 运行态状态必须有明确的创建、完成、超时、失败清理路径；清理只释放本次请求拥有的状态。
- 日志、接口、配置、提交信息默认不泄露密码、Token、密钥、设备口令等敏感信息。

## 二、分层与包结构

- 后端根目录：`src/main/java/com/genersoft/iot/vmp/`。
- `gb28181/`：SIP 信令、设备/通道、点播、级联；`jt1078/`：JT808/JT1078；`media/`：ZLMediaKit；`streamProxy/`、`streamPush/`：拉流/推流代理。
- `service/`：跨模块服务；`web/`、`vmanager/`：REST 接口；`conf/`：配置、安全、调度；`storager/`：Redis 缓存和持久化辅助。
- `web/gb28181/` 是外部兼容 API（多为 `/api/v1`），不要随意改响应结构；`gb28181/controller`、`vmanager` 是管理 API。
- 新增领域代码放到对应业务包，不要把所有工具类都塞进 `utils`。

## 三、命名与类型

- 类名 PascalCase，方法/字段 camelCase，常量 UPPER_SNAKE_CASE，包名小写。
- Service 接口统一 `I...Service`，实现 `...ServiceImpl`；DAO 统一 `...Mapper`，动态 SQL 放 `dao/provider/...Provider`。
- 请求对象用 `*Param`/`*Request`，响应对象用 `*Result`/`*Content`；分页统一 `PageInfo<T>`。
- 严格区分：
  - `deviceId`、`channelId`：国标编码，通常是 `String`；
  - `id`、`dataDeviceId`、`channelDbId`：数据库主键/外键，通常是 `Integer`。
  - 新增方法参数名必须让调用方一眼看出是“库 ID”还是“国标编码”，不要混用 `channelId`。
- 固定取值用 `ErrorCode`、`InviteErrorCode`、`ChannelDataType`、`InviteSessionType` 等常量/枚举，禁止在 Java 代码里散落 `1`、`200`、`-15` 这类魔法值。
- 简单 POJO 用 Lombok `@Data` 或 `@Getter/@Setter`；可能为空的布尔/数值用包装类型，内部确定非空的计数/标志可用 primitive。
- 对外字段名就是 JSON 字段名；重命名属于破坏性变更，必须考虑前后端兼容。

## 四、Controller 规范

- 方法必须是 `public`；`@RestController` 下不再重复写 `@ResponseBody`。
- 新接口必须有 `@Operation`、`@Parameter`、`@SecurityRequirement(name = JwtUtils.HEADER)`；兼容接口用 `@Hidden`。
- 参数校验优先在 Controller 入口完成：
  - 简单非空用 `Assert`；
  - 需要明确错误码时抛 `ControllerException(ErrorCode, msg)`。
- 业务异常抛 `ControllerException`，不要在 Controller 里大量 `try/catch` 后手工拼 `WVPResult`。
- 返回约定：
  - 普通接口可直接返回 DTO、`PageInfo`、`void`，由 `conf/GlobalResponseAdvice` 统一包成 `WVPResult`；
  - 需要自定义 `code/msg` 或异步回调时直接返回 `WVPResult<T>`；
  - `/api/v1`、`/api/video-`、`/index/hook` 等路径被排除在自动包装外，兼容接口必须保持原始 JSON。
- 分页参数统一 `page`、`count`；Service 内 `PageHelper.startPage(page, count)` 后必须紧接着执行查询，中间不要插入其他 SQL。
- 新接口按语义使用 `GET/POST/DELETE`，不要新增“GET 做写操作”的接口；已有兼容接口保持不动。
- 异步接口使用 `DeferredResult<WVPResult<T>>`，超时时间来自 `UserSetting`；`onTimeout` 只设置结果并通知 Service，不在 Controller 里直接删 Redis/播放状态。

## 五、Service 与事务

- Service 实现类使用 `@Service`、`@Slf4j`；对外暴露接口，不直接注入实现类。
- `@Transactional` 只放在 **ServiceImpl 的 public 方法** 上；不要放在 Controller 或 Service 接口上（现有少量例外，新代码不要模仿）。
- 事务只包数据库写操作；不要把 SIP 等待、ZLM HTTP 调用、Redis 轮询等耗时操作放进事务。
- 同类内部调用 `@Transactional`/`@Async` 方法会绕过代理；需要时拆到另一个 Bean 或自注入。
- 业务失败抛 `ControllerException`；异步/协议回调使用 `ErrorCallback<T>`，通过 `InviteErrorCode` 表达结果，不要跨线程抛异常。
- 查询单条允许返回 `null`，查询列表返回空集合而不是 `null`；调用方必须判空。
- 设备/平台 BYE、事务清理优先复用 `DialogTerminationService`，不要新增直接调用 `cmder.streamByeCmd` 的旁路。

## 六、DAO 与 SQL

- Mapper 使用 `@Mapper` + `@Repository`；多参数使用 `@Param`；插入需要回填主键时使用 `@Options(useGeneratedKeys = true, ...)`。
- 动态 SQL 统一放 `dao/provider`，不新增 XML Mapper。
- **所有外部参数必须用 `#{}` 绑定**；`${}` 只允许用于白名单排序字段或内部常量，禁止拼接用户输入。
- 集合 `IN` 查询使用 `<foreach>` + `#{list[i]}`；空集合/null 要跳过条件，避免生成 `IN ()`。
- 多数据库 SQL 按方言拆分：
  - `MysqlChannelUpsertProvider`、`PostgresStyleUpsertProvider`、`DmChannelUpsertProvider`、`H2ChannelUpsertProvider`；
  - 通过 `databaseId` 选择，修改 upsert/几何/分页 SQL 时必须检查所有受支持数据库。
- 表名统一 `wvp_` 前缀，字段 snake_case；Java 字段 camelCase。注意 `device_id` 是国标编码，`data_device_id` 是数据库外键，不能混用。
- 写操作返回影响行数；调用方按业务决定是否校验，不要用异常控制正常分支。
- 数据库脚本按版本维护在 `数据库/<version>/`，无 Flyway/Liquibase；结构变更要同步对应数据库的初始化/更新脚本。

## 七、Bean、DTO 与序列化

- 对外 DTO/Bean 字段加 `@Schema(description = "...")`；枚举/状态字段说明取值。
- 不要把含 `password`、`gbPassword`、`pushKey`、`token`、`secret` 的实体直接返回给前端；使用 DTO/VO，或至少加 `@JsonProperty(access = WRITE_ONLY)` / `@JsonIgnore`。
- HTTP 响应由 Spring Jackson 序列化；Redis 使用 fastjson2。敏感字段要同时检查两套序列化注解，不能只处理一边。
- 简单对象转换优先显式赋值；`BeanUtils.copyProperties` 只用于字段完全一致的场景，避免把敏感字段一起复制。
- `WVPResult` 只表达 HTTP 业务结果；`InviteErrorCode` 只用于点播/回放等异步回调，不要混用错误码体系。

## 八、异常与返回

- HTTP 业务错误统一返回 HTTP 200 + `WVPResult.code != 0`；只有认证失败、系统异常等才使用 4xx/5xx。
- 全局异常处理在 `conf/GlobalExceptionHandler`：
  - `ControllerException` 保留业务 code/msg；
  - `IllegalArgumentException` 当前映射为 `ERROR100`；
  - 其他异常返回 `ERROR500`。
- **不要把 SQL、文件路径、密钥、底层异常堆栈直接拼进返回给前端的 message**；详细原因写日志。
- 异步回调必须保证“恰好一次”：成功、失败、超时都要释放认领并通知所有等待者；单个回调抛异常不能影响其他回调。
- 点播等待使用 `onceAndFirst` 认领，只有首个请求负责发起 SIP；`updateInviteInfoForSSRC` 等更新路径不得清空仍在等待的回调。

## 九、日志与隐私

- 使用 Lombok `@Slf4j`，禁止新增 `System.out.println`、`printStackTrace`。
- 日志使用参数化占位符 `{}`，不要字符串拼接；异常对象放在最后一个参数。
- 统一使用中文 + 模块前缀，例如：
  - `log.info("[点播] deviceId={}, channelId={}", deviceId, channelId);`
  - `log.error("[录像下载] 处理失败: stream={}", stream, e);`
- 日志级别：生命周期/关键动作 `info`，参数细节 `debug`，可恢复异常 `warn`，失败/异常 `error`。
- 禁止记录密码、Token、Authorization、Redis 密码、设备口令、pushKey、完整配置对象；不要直接打印含敏感字段的实体 JSON。
- 现有 `ApiController.login` 在 debug 日志中打印 password，属于反例，不要照抄。
- 异常信息、提交信息、配置文件同样适用隐私规则。

## 十、配置与常量

- 成组配置用 `@ConfigurationProperties(prefix = "...")`，字段给默认值；单点配置才用 `@Value`。
- 配置项使用 kebab-case，Java 字段 camelCase；配置类通常加 `@Component`、`@Order(0)`。
- Redis key/前缀统一放 `common/VideoManagerConstants`，不要在业务代码里写字符串 key；按实例隔离的 key 加 `userSetting.getServerId()`。
- 临时状态必须设置 TTL；超时时间优先取 `UserSetting` 的配置，不要硬编码。
- 多键一致性操作使用 `SessionCallback` + `MULTI/EXEC`；需要“检查后删除”时使用 `WATCH/MULTI` 或 Lua，不能假设两次 Redis 调用原子。
- 本地 profile/密码不要提交；`application-*.yml` 多数被 gitignore，新增配置前先确认跟踪状态。

## 十一、并发、异步与状态

- 共享可变状态必须使用 `ConcurrentHashMap`、`CopyOnWriteArrayList`、`Atomic*` 等并发容器；不要用普通 `HashMap` 跨线程读写。
- 清理 Map 使用 `remove(key, expectedValue)` 条件删除，避免误删其他线程刚注册的新任务/新回调。
- 不要用 `synchronized (str.intern())` 锁设备/通道；按 key 锁优先参考 `CatalogDataManager`、`SSRCFactory` 的 `computeIfAbsent` 模式。
- 避免整个 Service 方法 `synchronized`；只锁必要的临界区。
- Redis 中的 SIP 事务以 `Call-ID` 为权威数据，`STREAM` 只是索引；删除 STREAM 索引前必须确认它仍指向当前事务，避免误删新会话。
- 延迟任务统一用 `DynamicTask`：key 全局唯一，任务完成/取消后必须移除 future，否则同 key 无法重新注册。
- `DeferredResult` 超时/完成只能成功一次；清理逻辑必须明确“我拥有哪个请求/哪个 claim”，不能按设备+通道盲删。
- 复杂并发方法必须用 Javadoc 写清楚：不变量、原子边界、并发窗口、失败兜底；参考 `DynamicTask.stop()`、`InviteStreamServiceImpl` 的注释风格。

## 十二、时间、空值与集合

- 时间统一走 `utils/DateUtil`，时区固定 `Asia/Shanghai`；不要新增 `SimpleDateFormat` 或自定义时间格式。
- 对外协议时间用 `DateUtil` 的 ISO8601/1078 格式转换；内部计算优先 `LocalDateTime`/`Instant`。
- 项目不使用 `Optional`；判空使用 Spring `ObjectUtils` / `StringUtils`，注意不要和 Apache Commons 的同名类混用。
- 列表/集合返回值用空集合，不返回 `null`；Map 同理。
- 字符串判空优先 `ObjectUtils.isEmpty`；需要业务错误时用 `ControllerException`，不要静默返回。

## 十三、测试

- 使用 JUnit 5 + Mockito；纯单元测试，不启动 Spring 上下文，不依赖 MySQL/Redis/ZLM。
- 测试类放在被测类同包，命名 `*Test`；方法名用英文 `method_condition_expected`，断言消息说明业务不变量。
- Mockito 统一 `@ExtendWith(MockitoExtension.class)`、`@Mock`、`@InjectMocks`。
- Provider/SQL 测试必须断言使用 `#{}`、不包含原始参数值；并发/清理测试要断言“旧任务被移除且新任务可注册”。
- 修 bug 必须补回归测试；至少覆盖失败、超时、重复调用、并发清理中的一个边界。
- 使用 JDK 21；`pom.xml` 当前硬编码 `<skipTests>true</skipTests>`，跑测试需 IDE 或临时改 `false`，跑完恢复。

## 十四、前端规范

- `web/` 是 Vue 2 + Element UI，不使用 Vue 3 Composition API。
- 遵循现有 ESLint：2 空格、单引号、无分号、对象花括号内留空格；提交前执行 `npm run lint`。
- 接口统一放 `web/src/api/*.js`，一个函数对应一个后端接口；统一使用 `@/utils/request`，不要在组件里直接 `axios`。
- 页面按后端 `WVPResult` 读取：`res.data.code`、`res.data.data`、`res.data.msg`，不要在前端重复包装。
- 组件放 `views/`、`components/`；全局状态放 Vuex module；路由 meta 控制权限。
- 前端不保存密码/密钥，不在 console 输出 Token；生产构建不要新增 mock 接口。
- `npm run build:prod` 输出到 `src/main/resources/static`，该目录被 gitignore，不要手工提交构建产物。

## 十五、提交与评审

- 提交信息以中文为主，动词开头，说明“做了什么/为什么”；可使用 `fix(模块):`、`feat:` 前缀。
- 一个提交只做一件事；不要混入无关格式化、重命名、依赖升级。
- PR 描述包含：背景、改动点、影响范围、验证方式、风险/回滚。
- 审核 PR 先用简要文字说明：**建议合并 / 可合并但有问题需处理 / 建议发回作者修改**。
- 发现重复逻辑时优先重构复用；不要为了快速修复复制一套新的清理/重试逻辑。

## 十六、存量中需要避免的反例

以下现状不要作为新代码模板：

- `IDeviceService` 接口上的 `@Transactional`、`UserApiKeyController` 上的 `@Transactional`：事务应下沉到 ServiceImpl。
- `DeviceServiceImpl` 中的 `synchronized (deviceId.intern())`：改用按 key 锁。
- `ApiController.login` 打印 password；`GlobalExceptionHandler` 把 `e.getMessage()` 返回前端。
- `Device`、`CommonGBChannel` 直接携带 `password/gbPassword` 返回；新增接口必须用 DTO 或序列化忽略。
- `ChannelProvider.queryInListByStatus` 直接拼接数值 ID：即使当前是内部数值，也应使用 `#{}`。
- `System.out`、`printStackTrace`、字符串拼接日志：新代码禁止。
