# 已有云录像的独立观看会话

适用场景：多人观看同一份已经生成、登记在云录像索引中的 MP4，各自定位、暂停、恢复和关闭。文件只保留一份，每位观看者有独立的 `sessionId` 和媒体源，不占用新的设备回放或下载连接。

## 接口

所有接口沿用 WVP 的 JWT / API key 认证及 `WVPResult` 包装，前缀为 `/api/cloud/record/sessions`。下文错误码指响应中的 `code`，保留现有HTTP响应语义。

| 方法 | 路径 | JSON 请求 | 行为 |
| --- | --- | --- | --- |
| POST | 空路径 | `{"cloudRecordId":123,"positionMs":0}` | 为已有录像创建独立会话，创建时位置默认 0 |
| GET | `/{sessionId}` | 无 | 查询状态；不续期 |
| POST | `/{sessionId}/seek` | `{"positionMs":12000}` | 定位；播放中返回新的媒体地址，暂停中只保存位置 |
| POST | `/{sessionId}/pause` | `{"positionMs":7000}` | 保存播放器实际位置，关闭自己的媒体源 |
| POST | `/{sessionId}/resume` | 无 | 从保存位置加载同一文件；正在播放时幂等返回现有地址 |
| DELETE | `/{sessionId}` | 无 | 关闭自己的媒体源及会话，重复关闭已结束会话成功 |

`cloudRecordId` 来自现有 `/api/cloud/record/list`。只接受数据库记录 ID，不接受客户端传入磁盘路径、媒体节点或任意流名。位置单位统一为**相对该文件起点的毫秒数**，范围 `[0, durationMs)`，最大 `4294967295`。本接口不跨文件拼接时间轴。

成功响应的 `data` 包含：

```json
{
  "sessionId": "服务端生成的UUID",
  "cloudRecordId": 123,
  "state": "playing",
  "positionMs": 12000,
  "durationMs": 60000,
  "expiresAt": 1790000000000,
  "serverId": "创建会话的WVP实例",
  "playback": {
    "app": "mp4_record",
    "stream": "session_唯一媒体身份",
    "mediaServerId": "录像所属节点",
    "fmp4": "原StreamContent格式的播放地址",
    "ws_fmp4": "原StreamContent格式的播放地址"
  }
}
```

`playback` 沿用 `StreamContent`，不返回媒体密钥或磁盘路径。暂停时为 `null`。`positionMs` 是最近一次明确设置的位置，不是服务端估算的实时进度。ZLM 按关键帧定位，实际首帧可能与请求位置有小幅偏差。

## 暂停和回收

现有 ZLM 版本的零倍速不是可用暂停接口，因此暂停采用“保存位置、关闭自己的源”，恢复时生成新流并用 `seek_ms` 定位。调用方必须上报播放器实际位置，并在恢复或播放中定位后替换媒体地址；仅调用浏览器 `video.pause()` 不等于暂停服务端源。

- 暂停状态保留 120 秒，成功响应通过 `expiresAt` 明确截止时间；过期后可用同一记录 ID 和本地保存位置创建新会话。
- 播放到 EOF、无人打开或读者离开后，由 ZLM 结束源，WVP 接收当前源离开事件后删除会话。无人观看延迟仍使用该节点的 `general.streamNoneReaderDelayMS`。
- 会话另有“文件剩余时长 + 120 秒”的最长存活时间；每 10 秒清扫过期状态。GET 不延长生存时间。关闭失败保留精确媒体身份，下次清扫重试，不假报已暂停。
- 定位或恢复时使用新的唯一流名，旧流迟到的离开事件不能结束替代流。不同会话各自加锁，关闭 A 不操作 B。
- 每实例最多保留 1024 个会话，达到容量时返回现有 `486` 错误；结束、关闭或清理成功后释放容量。
- 正常退出尽力关闭本实例的源。WVP 重启后会话状态不恢复，客户端收到 404 后重新创建；旧连接应断开，原媒体源仍受 EOF 和无人观看回收约束。

## 部署与兼容边界

1. 使用 ZLM 节点，配置 `record.fileRepeat=0`；全局循环播放配置会覆盖单次加载的 `file_repeat=0`。当前接口按正常速率播放，不提供倍速。
2. 录像必须已完成，文件仍位于云录像记录指定节点且该节点在线。原节点不可用时返回 `486`，不选择其他节点读取同一路径。未找到录像返回 `404`；非法位置或不支持的记录返回 `400`。
3. 创建与控制请求必须到同一个 WVP 实例；返回的 `serverId` 可供现有网关或调用方保持路由。不同实例归属的录像需在其所属 WVP 上调用，不增加新的跨实例会话 RPC。
4. 会话控制绑定 WVP 用户，其他 WVP 用户操作返回 `403` 且不调用媒体接口。关闭接口鉴权时沿用现有匿名模式。媒体 URL 沿用现有文件点播鉴权语义，是不可猜测的播放能力地址，不承诺绑定最终业务用户。
5. 业务系统使用同一 WVP 服务账号时，仍需由业务后端校验录像访问权限并将 `sessionId` 绑定到观看者；不能把 WVP 服务凭据交给浏览器。
6. 既有 `/api/playback` 设备回放和 `/api/cloud/record/loadRecord` 保持原行为。本接口不自动导出、不改变设备录像并发能力，也不把未完成文件当作可用文件。

## 接入方最小调整

- 将已就绪录像对应到现有云录像记录 ID，调用本接口创建每个播放器自己的会话；使用已有 `StreamContent` 媒体地址。
- 时间轴使用录像真实起点与文件偏移。拖动、暂停、恢复只提交本播放器的会话 ID，播放器位置正确换算为文件内毫秒，不使用当前系统时间代替录像时间。
- 定位和恢复后销毁旧连接并加载响应中的新地址。同一播放器的控制请求必须串行提交，可合并尚未发送的最新拖动目标；仅丢弃旧响应不能阻止已经在服务端执行的旧请求关闭新流。请求代次可额外防止关闭后的迟到UI更新，迟到的创建结果也要关闭其返回的会话。
- 关闭弹窗或切换通道时关闭当前会话并释放本地连接；失联由无人观看机制兜底。长暂停过期后保留本地位置，重新创建会话。
- 未命中已完成文件时维持明确的原设备回放入口或提示，不在同步取流接口内无限等待导出。本次无需增加归档表或准备任务框架。
